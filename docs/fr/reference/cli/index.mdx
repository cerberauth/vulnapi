## Usage global

```sh
vulnapi <command> [flags]
vulnapi --help
vulnapi version
```

Toutes les commandes retournent `0` en cas de succès et une valeur non nulle en cas d'erreur.

## Options globales

| Option | Description |
|---|---|
| `--sqa-opt-out` | Se désinscrire des statistiques d'usage anonymes et des rapports de crash |
| `-h, --help` | Afficher l'aide pour n'importe quelle commande |

## Options communes

Toutes les commandes `scan` et `discover` partagent ces options. Les options du client HTTP suivent les mêmes conventions que `curl`.

| Option | Par défaut | Description |
|---|---|---|
| `--rate <rate>` | `` | Limite de débit des requêtes (ex. `10/s`, `1/m`) |
| `-x, --proxy <url>` | `` | URL de proxy pour toutes les requêtes |
| `-H, --header <header>` | `` | En-tête à inclure dans les requêtes (répétable) |
| `-b, --cookie <cookie>` | `` | Cookie à inclure dans les requêtes (répétable) |
| `-u, --user <user:pass>` | `` | Nom d'utilisateur et mot de passe pour l'authentification HTTP Basic |
| `--basic` | `` | Utiliser l'authentification HTTP Basic (avec `-u`) |
| `--digest` | `` | Utiliser l'authentification HTTP Digest (avec `-u`) |
| `--scans <scan-id>` | `` | Exécuter uniquement des scans spécifiques (répétable ; supporte les jokers comme `jwt.*`) |
| `--exclude-scans <scan-id>` | `` | Exclure des scans spécifiques (répétable ; mêmes motifs que `--scans`) |
| `--jwt-secret <secret>` | `` | Secret HMAC connu du JWT testé, utilisé pour re-signer les tokens modifiés |
| `--jwt-other-audience-token <token>` | `` | JWT validement signé émis pour une autre audience, envoyé par `jwt.audience_not_validated` |
| `--jwt-other-issuer-token <token>` | `` | JWT validement signé émis par un autre émetteur du même fournisseur d'identité, envoyé par `jwt.issuer_not_validated` |
| `--jwt-max-lifetime <duration>` | `24h` | Durée de vie au-delà de laquelle `jwt.long_lifetime` signale le token |
| `--report-format <format>` | `table` | Format de sortie : `table`, `json`, `yaml` |
| `--report-transport <transport>` | `file` | Transport du rapport : `file`, `http` |
| `--report-file <path>` | `` | Chemin du fichier où écrire le rapport |
| `--report-url <url>` | `` | URL vers laquelle envoyer le rapport (avec `--report-transport http`) |
| `--no-progress` | `false` | Désactiver la barre de progression |
| `--severity-threshold <score>` | `1.0` | Seuil CVSS au-dessus duquel la sortie est aussi écrite sur stderr |
| `--only-scans-above-threshold` | `false` | N'exécute que les contrôles pouvant atteindre `--severity-threshold` ; échoue sur n'importe quel résultat puisque tous peuvent l'atteindre |
| `--allow-unsafe-methods` | `false` | Autorise les contrôles à envoyer des méthodes HTTP non sûres (`POST`, `PUT`, `PATCH`, `DELETE`) avec des identifiants valides |

> **Déprécié :** `--rate-limit` (`-r`) a été remplacé par `--rate`. L'ancienne option est toujours acceptée en tant qu'alias.

## Options d'authentification

`scan openapi`, `scan curl` et `scan graphql` acceptent ces options pour obtenir l'identifiant testé. Voir [Scan authentifié](../../authenticated-scanning).

| Option | Défaut | Description |
|---|---|---|
| `--client-id <id>` | `` | Client ID OAuth2 (env `VULNAPI_CLIENT_ID`) |
| `--client-secret <secret>` | `` | Client secret OAuth2 (env `VULNAPI_CLIENT_SECRET`) |
| `--token-url <url>` | `` | Endpoint de token OAuth2, remplaçant celui du schéma de sécurité |
| `--oauth2-scope <scope>` | `` | Scope OAuth2 à demander (répétable) |
| `--oauth2-username <utilisateur>` | `` | Utilisateur pour le flow OAuth2 password (env `VULNAPI_OAUTH2_USERNAME`) |
| `--oauth2-password <mot-de-passe>` | `` | Mot de passe pour le flow OAuth2 password (env `VULNAPI_OAUTH2_PASSWORD`) |
| `--login-command <commande>` | `` | Commande affichant le token sur stdout |
| `--login-url <url>` | `` | Endpoint de connexion renvoyant le token en JSON |
| `--login-data <corps>` | `` | Corps envoyé à `--login-url` (JSON ou form encoded) |
| `--login-token-field <chemin>` | `access_token` | Champ de la réponse de connexion contenant le token |
| `--jwt-public-key <chemin-ou-url>` | `` | Clé publique PEM du JWT testé |

## Comportement de sortie

Lorsqu'au moins un résultat a un score CVSS supérieur à `--severity-threshold`, VulnAPI écrit la sortie sur **stderr** en plus de stdout. Cela déclenche automatiquement les patterns `|| exit 1` et les contrôles d'échec en CI/CD. Le seuil par défaut est `1.0`, ce qui signifie que tout résultat avec un CVSS > 1.0 déclenche une sortie sur stderr.

Ajoutez `--only-scans-above-threshold` pour ignorer avant l'analyse tout contrôle qui ne pourrait pas atteindre ce seuil. Puisque tous les contrôles exécutés peuvent alors l'atteindre, VulnAPI échoue sur n'importe quel résultat.
